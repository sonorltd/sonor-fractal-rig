Fractal Rig — how it all fits together

    
One Raspberry Pi is the master. Every other Pi is a renderer driving a projector over HDMI (the master renders too, so it is projector #1). The master broadcasts the whole state — animation clock, beat grid and all 20 parameters — in one 120-byte UDP multicast packet, 60 times a second. Every renderer draws the same GPU shader from the same numbers, so N projectors move as one. There are no sessions and no handshakes: power a Pi on and it is in sync within one packet.

Sources — what drives the picture

    
All sources feed one engine on the master. Human inputs (this page, MIDI, OSC, presets) set a base value per parameter — last write wins. Auto-drift adds a slow offset on top of anything with the pink toggle. Audio, when running, owns energy and bass outright. Tempo has a priority order: Pro DJ Link if a beat has been seen in the last 5 s, else tap / typed BPM, else the audio onset guess. The Sources panel on the Control tab shows a live dot for each: green = linked and delivering, amber = enabled but waiting for a device/packets, grey = switched off.


    
Web UI (this page)

    
Served by the master at http://<master-ip>:8080/; works on a phone. Every parameter has a slider and an auto-drift toggle; presets save the sliders and which ones are drifting. Space = tap tempo, 1 = set beat 1 (re-align the bar to the music without changing BPM — the pulse and bar-swing follow instantly on every projector). When no master is reachable (e.g. the GitHub Pages copy) the page runs a local simulation of the engine — "demo mode" — with the identical shader in the preview.


    
Pro DJ Link (XDJ-RX2 / CDJ / DJM)

    
Every Pioneer player with a LINK port broadcasts a small packet on every beat (UDP 50001): deck number, track BPM, pitch fader position and beat-in-bar 1–4. The master only listens — it never joins as a virtual CDJ, never claims a player number, and nothing appears on the decks. It records the animation-clock time of each beat plus the effective BPM (track BPM × pitch); the shader derives beat phase from those, so beat_pulse and bar_swing land exactly on the grid and stay locked between packets. Follow mode "auto" hands over to whichever deck beat most recently (natural during a mix); or pin deck 1/2. Needs: one Ethernet cable from the LINK port to the rig's switch — see Network.


    
Audio in

    
Optional. Any class-compliant USB audio input on the master (USB interface, the XDJ's USB audio, or a mic pointed at the room). ~40× a second the master computes overall loudness and a 30–150 Hz bass band, auto-gained so they sit mid-range whatever the volume, and writes them to energy (brightness / saturation lift) and bass (warmth + punch). A crude onset detector supplies beats only when Pro DJ Link is not locked — expect it to wander on breakdowns. Pick the input device in the Sources panel; needs libportaudio2 + sounddevice numpy (installer adds them on the master).


    
MIDI

    
Any class-compliant controller on the master's USB. CC → parameter via midi_map in config.json; defaults: CC1 zoom, CC2 rotation, CC3 hue, CC4 hue spread, CC5 warp, CC6 glow, CC7 brightness, CC8 contrast, CC9/10 Julia re/im, CC11 beat pulse, CC12 kaleidoscope. Notes 36+ recall presets in order, note 35 = tap, note 34 = set beat 1, notes 33 / 32 = next / previous projectM preset. "Map last CC →" on the Control tab learns a knob for this session (copy into config to keep). Reconnects automatically. Tip: the XDJ-RX2 is itself a USB MIDI controller when not in rekordbox mode.


    
OSC

    
UDP 9000. /frx/<param> f (e.g. /frx/hue 0.5), /frx/tap, /frx/beat1, /frx/bpm f, /frx/preset s|i, /frx/auto_<param> 0|1, /frx/pm_next · /frx/pm_prev · /frx/pm_random. TouchOSC, Lemur, Ableton (Max for Live / OSC plugins), Resolume, QLab and Beat Link Trigger all speak this — it is the bolt-on route for anything not built in.


    
Ableton Link

    
A tempo source and an output: follow a Link session (Resolume / Ableton / Traktor) or lead it with the CDJ grid. See the Resolume section.


    
Autonomous

    
Parameters with the pink toggle wander on smooth noise around wherever you left their slider. "Auto depth" is how far, "Auto rate" how fast; zoom drifts deliberately shallower. The Sources toggle pauses all drift at once without losing which params were selected. With nothing else plugged in the rig runs itself indefinitely.


    
Inputs monitor — seeing what the master hears

    
The card under Tempo on the Control tab is a live scope of every input, drawn at display rate from the same clock the Pis use, so what you see is what the projectors are pulsing to:

    
    
      
  • Lock badge — green LOCKED when tempo comes from Pro DJ Link (with the deck it is following) or Ableton Link (with peer count); amber FREE-RUNNING for tap / typed BPM or audio-onset estimates; grey when there is no tempo. Next to it: bar · beat position in the grid and the ± BPM spread over the last 8 s — a locked source sits at ±0.00, a tap will read ±0.5–2 until it settles, a wandering onset detector shows red.
    • 
      
  • Beat grid — 4 bars × 4 beats. The white playhead moves with the master clock; the current cell flashes and fades within the beat; bar-1 cells are outlined. Bar alignment is whatever the last downbeat set (Pro DJ Link beat 1, Link phase, or SET BEAT 1); the four-bar phrase position is relative to that, so if a phrase feels off by a bar it is the DJ's grid, not the rig.
    • 
      
  • Deck lanes — one row per Pro DJ Link deck heard: BPM (track × pitch), its beat 1–4 boxes lit from the deck's own packets, "live" or the age of its last beat, and which deck the master is following. Two decks with different beat boxes lit is normal mid-mix; the rig follows the most recent beat (or the pinned deck).
    • 
      
  • Link lane — when Ableton Link has peers: session tempo, peer count, follow / lead, and a bar-phase bar.
    • 
      
  • Waveform + spectrum — with Audio in enabled: ~96-sample oscilloscope of the input, 16 log-spaced bands 40 Hz–16 kHz with peak-hold ticks, and Energy / Bass meters (exactly the values written to the energy and bass params). The master streams these to the page at 15 Hz. Audio off, or the Pages demo, shows a dimmed synthetic beat-locked signal so the layout is visible — labelled as such.
    • 
      
  • Activity chips — MIDI (last CC / note, pulses on each message), OSC (last address + value), Pro DJ Link (packets per second and beats counted). A chip that never pulses while you turn a knob is the fastest "is it even arriving" check before opening the Status tab.
    • 
    

    
Perform mode carries a slim copy of the beat grid under TAP / SET BEAT 1, so the bar can be checked at arm's length.

  


  

    
Scenes & controls

    

      
0 MandelbrotThe classic set. Zoom into the boundary (Seahorse valley preset); iterations = detail, glow = orbit-trap light inside the set.

      
1 JuliaJulia set for seed julia_x/y. Put those on auto-drift for endlessly morphing shapes.

      
2 Burning ShipAbs-value variant — ship / flame structures. Rotation ≈ π shows it upright.

      
3 TricornConjugate variant — three-fold symmetry, pairs well with kaleido.

      
4 PlasmaClassic demoscene plasma. warp adds noise turbulence, iterations = banding, hue_spread = colour cycles.

      
5 TunnelWinamp/AVS-style infinite tunnel. iterations = spoke count, warp = twist, beat_pulse lunges forward on the kick.

      
6 StarfieldHyperspace warp. warp = streak length, iterations = star layers, beat pulse = speed burst.

      
7 WavesOscilloscope wave stack — the Milkdrop feel. energy/bass (live from audio) set amplitude and ripple; iterations = number of traces.

      
8 projectMReal Milkdrop presets via libprojectM 4 on each Pi. Pick presets in the projectM card; pm_mix blends in our post-pass (kaleido / zoom / rotate / hue) on top. See the projectM section below.

    

    
Scenes 0–7 are one shader, so kaleido, rotation, zoom, the palette controls, beat_pulse and bar_swing work on every scene, and switching scenes is one integer in the packet — all projectors flip on the same frame. Adding a scene is a function in renderer/shaders/fractal.frag and a name in the mode list.

    
Scene 8 — Milkdrop (projectM engine)

    
Each Pi runs libprojectM 4 (built for GLES by setup/install-projectm.sh) and renders the real .milk preset files — the original Winamp Milkdrop pack (~550) and optionally Cream of the Crop (~10,000). The master owns preset selection: the current preset's index in the sorted list rides in the packet as pm_preset, so every Pi loads the same file on the same frame, with a pm_blend-second crossfade. Prev / next / random / search / auto-cycle every N bars live in the projectM card; OSC /frx/pm_next|pm_prev|pm_random; MIDI notes 33 / 32.

    
Audio: projectM needs a waveform. When the master's audio input is running it multicasts the PCM to the Pis (udp/5007, ~700 kbit/s) so every preset reacts to the room. Without it, each Pi synthesises an identical beat-locked kick + hat from the shared clock and BPM — presets still pump on the beat, and because the signal is derived from the same numbers it is the same on every Pi.

    
Honesty about sync: Milkdrop presets use their own frame timing and random numbers, so two Pis on the same preset with the same audio look alike — same preset, same colours, same beat reaction — but are not pixel-identical, and they drift apart over minutes until the next preset change re-aligns them. That is fine for "same vibe on every projector" and for the family-of-variations layout; it is wrong for a seamless tiled wall (you'll see the seams move). Use scenes 0–7 for tiled walls. pm_mix runs projectM's frame through our post-pass so kaleidoscope, rotation, zoom, hue shift and beat pulse still apply.

    
Browser preview: the Live preview runs Butterchurn (Milkdrop 2 in WebGL, vendored so it works on the gig LAN with no internet) fed the same beat-locked synthetic audio the Pis use. Where the browser pack contains the same-named preset as the Pis (most of the original Milkdrop pack) you see the real preset; otherwise the closest name, labelled as such. It's a simulation of what the wall is doing, not a pixel copy.

    
Install (every Pi + master, ~15 min each): sudo bash setup/install-projectm.sh (add --cream for the big pack). The preset count must be identical on all Pis and the master — the Renderers table flags any Pi whose count differs, because preset numbers would then point at different files. Pi 5 renders most presets at 1080p/0.6 scale comfortably; Pi 4 is happier at scale 0.5.

    
Cheat-sheet

    

      
zoomlog2 magnification (each +1 doubles). Float precision runs out around 22–24 on fractals.

      
center_x / yPan. Also pans the non-fractal scenes.

      
kaleido0 = off; 2–16 mirror segments. Applied before everything else, so it works on all scenes.

      
hue / hue_spread / hue_speedBase colour, how many colour cycles across the gradient, automatic colour cycling rate (negative = reverse).

      
contrast / brightnessGamma-style contrast (keeps blacks black — projectors love black) and output gain.

      
beat_pulse / bar_swingKick per beat (zoom + brightness) and a slow sway per 4-beat bar. Need a tempo source.

      
Clock speedRate of the master's animation clock. 0 freezes motion everywhere; 2 doubles it.

    

  


  

    
Pi setup

    
Shopping list

    
    
      
  • Raspberry Pi 5 (best) or Pi 4, one per projector. Pi 5 does 1080p ≈ 60 fps at the default render scale 0.6 with 150–300 iterations; Pi 4 use scale 0.5 / ~120 iterations. Pi Zero 2 W works at scale 0.35 for simpler scenes.
    • 
      
  • RAM: the 2 GB Pi 5 is fine for a renderer and for the master (renderer ≈ 60 MB, master ≈ 80 MB, projectM adds ~150 MB, and the projectM build script drops to 2 jobs on 2 GB boards). Go 4 GB only if the same Pi will also run the Chromium touchscreen kiosk. Storage: a 32 GB card is enough, 64 GB is comfortable (OS ≈ 5 GB, projectM source + build ≈ 1 GB, Cream-of-the-Crop presets ≈ 100 MB); use an A2-rated card or an NVMe HAT on the master for faster boots.
    • 
      
  • Official PSU per Pi (27 W for Pi 5, 15 W for Pi 4) — under-powered Pis throttle the GPU. micro-HDMI → HDMI cable per projector.
    • 
      
  • A cheap gigabit switch and patch leads. Wired beats Wi-Fi: multicast on Wi-Fi jitters 20–50 ms and gets dropped under load; wired is <1 ms.
    • 
      
  • Master extras: a small router/DHCP if the XDJ is on the same switch, a MIDI controller and/or USB audio input if you want them.
    • 
      
  • microSD 16 GB+ (or NVMe on Pi 5) with Raspberry Pi OS Bookworm Lite (64-bit). Lite is preferred: the renderer draws straight to HDMI via KMSDRM with no desktop in the way.
    •

Layouts

    
Renderer arguments go on the install line (or sudo systemctl edit fractal-renderer). Mix freely per Pi.

    

      
(nothing)Same image everywhere. Simplest, most forgiving. Default.

Network & Pro DJ Link

    
    
      
  • All Pis on one wired switch, one subnet. Multicast group 239.255.42.1:5005, TTL 1 — never leaves the LAN. Renderers heartbeat back to the master on UDP 5006.
    • 
      
  • Pioneer gear with no DHCP self-assigns 169.254.x.x. Either put a small router (DHCP) on the same switch so the XDJ and Pis share a subnet, or give the master Pi a second address: sudo nmcli con mod "Wired connection 1" +ipv4.addresses 169.254.42.10/16 && sudo nmcli con up "Wired connection 1".
    • 
      
  • Beat packets are broadcast, so the master only needs to be on the same layer-2 segment as the LINK port. Nothing is sent to the decks.
    • 
      
  • Managed switches: leave IGMP snooping off for this VLAN (or make sure a querier exists), otherwise multicast may be pruned after a minute or two.
    • 
      
  • A laptop on the same LAN can run the master instead of a Pi (python3 master/master.py) — handy for development.
    • 
      
  • Want deck names, on-air state or which deck is tempo master? Run Beat Link Trigger on a laptop and have it send OSC to the master.

Sync protocol (short version)

    
Packet: magic FRX1, version, param count, sequence, flags, t (master clock, f64), beat_t (clock time of the last beat, f64), bpm, bar_beat, then 20 floats in the order of master/params.py. Renderers store (t, arrival) and render at t + (now − arrival) — re-anchored 60× a second, so there is no drift to correct. Continuous params are smoothed (τ 60 ms) identically on every Pi; discrete ones (scene, iterations, kaleido) snap. Beats are never sent as a phase — the shader computes fract((t − beat_t)·bpm/60) itself, so it can't wrap mid-interpolation. Lose the master for 3 s and a Pi freewheels on its own clock, then re-locks silently. HDMI outputs are not genlocked, so adjacent projectors can be up to one frame (16 ms) apart — invisible at normal speeds. Full detail in PROTOCOL.md.

  


  

    
Perform mode & touchscreen console

    
▶ PERFORM (header button, key P, or open ?perf=1) replaces the whole page with big touch controls in four swipeable pages — Show (TAP, SET BEAT 1, engine, scenes, blackout / freeze / auto), Presets (shader presets, projectM prev / random / next / hold, your ★ favourites as tiles), Feel (brightness, contrast, glow, beat pulse, bar swing, warp, speed, auto depth, zoom / kaleidoscope / detail steppers) and Colour (hue swatches and sliders). Swipe or tap the page names; ✕ EXIT (or Esc) returns to the full GUI with every micro-control. The mode is remembered per browser.

    
Raspberry Pi touchscreen

    
Yes — the official 7" Touch Display (800×480), Touch Display 2 (720×1280) or any HDMI touch monitor works as a dedicated console: it is just Chromium showing this page. sudo bash setup/install-kiosk.sh http://fractal-master.local:8080/?perf=1 on a Pi does the whole thing — on Pi OS Lite it installs cage (one-window Wayland kiosk) + Chromium and boots straight into Perform mode; on Pi OS Desktop it adds an autostart entry instead. Touch works out of the box under Wayland.

    
    
      
  • Best: a separate console Pi (Pi 4 2 GB is plenty) with the touchscreen, on the same switch. The master keeps running headless with KMSDRM on its projector.
    • 
      
  • Same Pi as a projector: KMSDRM can't share the GPU with a compositor, so use Pi OS Desktop on that Pi, remove SDL_VIDEODRIVER=KMSDRM from fractal-renderer.service and add --display 1 so the renderer goes fullscreen on the HDMI output while the kiosk owns the touchscreen.
    • 
      
  • Any phone or tablet does the same job with no install — the layout is fully mobile-adaptive.

Resolume & Ableton Link

    
Everything lives in the Outputs tab. Three separate integrations, use any combination:

    
1 · Getting the rig's picture into Resolume

    
HDMI capture card (Cam Link 4K, Magewell USB Capture, ~£90–£300) on any Pi's HDMI — zero software, ~2 frames latency, never crashes. The rig appears in Resolume as a live source you can layer, mask, effect and pixel-map. This is the recommended route. Alternatively NDI over the network — see the NDI section.

    
2 · Tempo & bar lock — Ableton Link

    
Enable Link in Resolume (Preferences → Tempo → Ableton Link); the rig shows it as a peer. Follow: the rig takes tempo and bar phase from the Link session (Resolume, Ableton, Traktor, anything on the LAN can be the leader). Lead: the rig pushes its own tempo — from the XDJ's Pro DJ Link grid or tap — into the session and forces bar 1 on SET BEAT 1, so Resolume's beat-synced effects follow the CDJs through us. Tempo priority on the master when several sources are live: Pro DJ Link, then Link (follow), then tap / typed BPM, then audio onset. Needs aalink in the master venv (install.sh master adds it).

    
3 · OSC to Resolume — tempo, resync, scenes, parameters

    
In Resolume: Preferences → OSC → enable OSC Input, note the port (7000 default) and the PC's IP; enter both in the Outputs tab and switch on. The rig then sends the tempo whenever it changes (/composition/tempocontroller/tempo, normalised over Resolume's 20–500 BPM range), a resync on every SET BEAT 1, optionally /composition/columns/N/connect when a scene is selected (Scene → column map), and any rig parameter you map to a Resolume address (values 0–1, max 20/s). Find any Resolume parameter's OSC address in its Shortcuts → OSC panel. The reverse works too: Resolume's OSC Output can drive /frx/<param> on udp/9000, so a Resolume dashboard fader can move the rig.

    
4 · Resolume driving the LEDs instead

    
If you have Arena, its Advanced Output already pixel-maps Art-Net from any layer — with the rig's video in Resolume via capture card, Resolume can drive the strips and you can skip the LED section. Avenue can't, hence ours.

  


  

    
NDI video

    
NDI publishes a Pi's picture as a network video source for Resolume, OBS, vMix, TouchDesigner… The NDI SDK is a free licence-click download, so it can't ship in the repo: download NDI SDK for Linux from ndi.video, then on the Pi sudo bash setup/install-ndi.sh ~/Install_NDI_SDK_v6_Linux.tar.gz (installs headers + libndi, rebuilds the renderer with NDI), and add --ndi to that renderer's arguments (sudo systemctl edit fractal-renderer). The source appears as "Fractal Rig (pi-name)". Frames are sent at the render scale (1080p × 0.6 = 1152×648) at up to --ndi-fps (30 default) — a Pi 5 is comfortable there; ~40 Mbit/s on the LAN. The Outputs tab shows per-Pi NDI state (off / publishing / receiver connected). Use a wired switch; NDI over Wi-Fi is not a good evening.

  


  

    
Saving & the cloud (Supabase)

    
Every save in the app lands on the master Pi first — shows (master/shows/), the preset bank, the cue stack, LED configurations (master/led_configs/), each projector's mapping and config.local.json — so the rig works exactly the same with no internet at a venue. Whenever the Pi can reach Supabase (table studio_fractal_docs in the Sonor project) it pushes queued changes and pulls anything newer, last write wins; deletes propagate too. Shows and LED configurations are shared between rigs, so a setup made on the studio bench is in the "☁ from cloud…" menu on any other master; presets, cues, mappings and config are kept per rig name. The top-bar pill shows the state: green = in sync, amber = offline with changes queued (they go up when you're back on Wi-Fi), grey = not configured or paused. Settings, "Sync now" and "Pull everything" are on the Rig tab. Files still export and import as before (.fractalshow.json / .zip, .fractalleds.json) for moving things by hand or keeping a copy.

  


  

    
Cues, fades and audio modulation

    
Cues are the sequencing layer: a stack of steps for the set. Build one by setting the rig up and pressing Capture current look as cue (every parameter goes in), or add an empty cue and pick actions: scene, a saved preset, a whole show, projectM (random / next / a named preset), video (a clip, LIVE, next), feed mix, brightness or blackout, auto-drift on/off. Fade (bars) glides every continuous parameter over that many bars at the current tempo (discrete ones like scene switch at the start); Auto-follow fires the next cue after N bars, so a whole intro can run itself. GO / BACK live on the Cues tab and the Perform CUES page, keys G / B, MIDI notes 27 / 26, OSC /frx/go, /frx/back, /frx/cue n. The stack is saved with a show. Audio → parameters (Inputs tab) makes any parameter follow the music: pick a source (one of the 16 analyser bands, bass, overall energy, or the beat pulse that works from any tempo source), an amount (a fraction of the parameter's range — small numbers) and attack / release times; the level bars show each envelope live. Modulation sits on top of your sliders and auto-drift and never touches the Pis — they still just receive numbers.

  


  

    
Updating and restarting from the web page

    
Rig tab → Update everything from GitHub pulls the repo and re-runs the installer on the master and every renderer that is online (each Pi's fractal-media-sync status service on port 8082 accepts /update, /restart, /reboot from the master; setup/rig-update reads the role and renderer arguments back from the systemd units so nothing has to be typed). Per-Pi buttons do the same for one machine, and status opens that Pi's page (log, temperature, clips, mapping, update log). Expect 1–3 minutes of dark projectors while they rebuild; the ver column in the Projectors table goes amber for any Pi not on the master's version.

  


  

    
Resolume tab (two-way)

    
Picture out: the master renderer runs --ndi (headless on the rig, --headless --ndi) and appears in Resolume's Sources → NDI Servers. Picture back: Resolume's NDI screen (Output → Advanced → + Screen → NDI) is picked up on Outputs → NDI → Use as LIVE and multicast to every projector. Feed mix (live_mix, blend live_blend: crossfade / add / multiply / screen / difference) fades each projector between its own picture and that feed — works on every scene except while a video clip plays (one decoder per Pi). Control out: the clip pad (layers × columns, labels are yours), column launch, layer opacity / bypass / solo, composition master, tap and resync all send OSC to Resolume's OSC input (Preferences → OSC, default port 7000, set the host on the Connection card). Control in: turn on Resolume's OSC output aimed at the master, port 9000; move a knob, choose a rig parameter, press Map — Resolume's 0–1 values drive it. Mappings, pad size and labels are saved with a show.

  


  

    
Video & HDMI capture (scene 9)

    
How it stays in sync without streaming. Every Pi keeps an identical copy of the clip library (fractal-media-sync pulls it from the master over HTTP and keeps it current). The master never sends frames — it broadcasts clip number, the master-clock time it started, speed and loop in the same 60 Hz packet as everything else. Each renderer decodes its local file with libmpv (hardware H.264 on a Pi 4, software on a Pi 5 — both fine at 1080p) and nudges playback by up to ±8 % or seeks when it drifts more than 0.35 s from (t − t0) × speed. Result: every projector shows the same frame, and the video goes through the same post-pass as projectM, so kaleidoscope / tiling / zoom / hue still apply via Shader mix.

    
Uploading. Media tab → drop anything (mp4, mov, mkv, avi, webm, m4v, mpg, ts, gif…). The master converts to ≤1080p H.264 (yuv420p, 2-second keyframes, no audio, fast-start) so a Pi 4 can decode it; files that are already Pi-friendly are only remuxed. The library is byte-sorted by file name and that order is the clip index every Pi uses — the Projectors table shows a media column so you can see a Pi that hasn't caught up (3/4). Names are limited to letters, digits, - _ ..

    
Triggers. Engine card → VIDEO, or the clip tiles on the Perform Show page; playlist with auto-advance at clip end / every N bars / off, and bar sync restarts the clip on beat 1. OSC: /frx/video <index|name>, /frx/video_next, /frx/video_prev, /frx/video_restart, /frx/video_live. MIDI notes: 31 next · 30 prev · 29 restart · 28 LIVE (35 tap, 34 beat 1, 33/32 projectM stay as before).

    
LIVE (clip 255) and HDMI capture. The one case that is a stream: the master runs ffmpeg and multicasts MPEG-TS on udp://239.255.42.2:5010; every Pi tunes to it with mpv's low-latency profile (about 0.3–0.6 s behind, identical on all projectors). Sources: NDI — Resolume Arena/Avenue (Output → NDI), OBS, vMix or any NDI sender on the wired LAN, no capture card: the master needs the NDI SDK once (sudo bash setup/install-ndi.sh <SDK.tar.gz>, which also builds the ndi-recv helper), then pick the source by name; "low bandwidth" takes NDI's proxy stream (~640 px) for a fraction of the CPU. Full 1080p NDI is ~100–150 Mbit/s and the Pi 5 has to decode it and re-encode H.264, so 1080p30 is the comfortable ceiling; HDMI — a USB 3 UVC capture dongle (the £15 "HDMI to USB" sticks work; they appear as /dev/videoN, MJPEG 1080p30) plugged into the master; V4L2 — any camera; File — loop a clip from the library through the stream; Test — colour bars. Pick the device in the LIVE source card on the Media tab, START, then LIVE on the Video card. Live needs the wired switch just like the sync packets — a Wi-Fi hop drops too many multicast packets for video.

    
Files on the Pis. /var/lib/fractal-rig/media/*.mp4 (synced), /var/lib/fractal-rig/state (the renderer's note of the master's IP, read by the sync helper). On the master the library is master/media/ (gitignored). journalctl -fu fractal-media-sync shows the pulls; each Pi also has a status page on port 8082 with the renderer log, temperature/throttling, clip list and a link back here.

  


  

    
Projection mapping (Outputs → Projection mapping)

    
Per projector, edited here and applied on the Pi within a couple of seconds: keystone (drag the four corners onto the surface — turn on Test pattern and the projector shows a grid with the same red / green / blue / yellow corners), masks (polygons drawn in output space that are blacked out with an adjustable feather — a doorway, a speaker stack, the ceiling), soft-edge blend widths per side for overlapping projectors (gamma-shaped ramps so the overlap doesn't look brighter), brightness and gamma to match two different projectors. Arrow keys nudge the selected point by one projector pixel, Shift for ten. Copy from… clones another projector's setup as a starting point.

    
Under the hood: the master stores master/mapping/<name>.json and serves it as a small text file (/api/mapping/<name>.txt); fractal-media-sync writes it to /var/lib/fractal-rig/mapping.txt on that Pi; the renderer re-reads it when it changes and, when it's not identity, runs one extra full-resolution pass (inverse homography + mask texture + blend) instead of the plain upscale blit — about 1 ms on a Pi 5, free enough to leave on. The heartbeat reports a hash of the applied file, which is what the status pill ("applied on projector") checks. An identity mapping deletes the file so the Pi goes back to the zero-cost path.

  


  

    
Output resolution (top bar: Auto / 1080p / 4K)

    
A global choice broadcast to every renderer. 1080p is the default at every boot (config out_res_boot to change). Auto = whatever mode the screen came up in (a 4K TV on a Pi 4 means a 4K framebuffer, and the Pi 4 struggles — that was the "laggy / steppy" Pi 4). 1080p forces 1920×1080 ≤ 60 Hz on every projector, which is what you want on a Pi 4 and on most projectors anyway; 4K forces 3840×2160 where the screen offers it (a Pi 5 can drive it; the internal render scale still applies). Under KMSDRM a mode can only be chosen when the renderer starts, so a change makes each renderer remember the request, exit, and come straight back in the new mode — about 3 seconds of black per projector, so don't do it mid-set. A screen that doesn't have the mode keeps its current one (no restart loop). To pin one Pi regardless of the selector, give its renderer --out-res 1080 (or 4k / auto) in the install arguments.

  


  

    
LED pixel strips

    
An LED strip is treated as a very thin, very low-resolution projector: a straight line of sample points on the same canvas the projectors show. Each renderer streams an 80×45 thumbnail of its frame to the master 20× a second; the master samples the strip positions, applies gamma and brightness, and sends the pixel data to your controllers at the LED frame rate (40 fps default). Because the sample comes from the same packet-driven frame, the LEDs kick on the exact same beat as the projectors. All of it is configured in Outputs → LED pixel strips.

    
Controllers

    

      
WLED (ESP32)Best value: a £10 ESP32 board flashed from install.wled.me, a level shifter (74AHCT125) for 5 V data, up to ~800 WS2812 pixels per board. In WLED: Config → LED Preferences (count, type, colour order), Config → Sync → enable DDP (Realtime) — then use protocol ddp here. One WLED device = one strip line (or split its pixels across several lines with start pixel via multiple entries — coming). E1.31/Art-Net also work if you prefer.

      
Advatek / PixLite / Falcon / ECG-P2Pro pixel controllers speak Art-Net and sACN: set the controller's first universe per output, then give each strip line here the same universe; a strip longer than 170 pixels automatically continues into the next universes. sACN with IP multicast uses the standard 239.255.x.y groups (switch must pass multicast — same as our own sync).

      
Strip typeWS2812B / WS2815 (12 V, better for long runs) = colour order GRB, 60 px/m typical. SK6812 RGBW: set the controller to RGB mode. APA102/SK9822: fast, usually BGR.

    

    
Layout

    
Each row in the strip table is a run: name, controller IP, protocol, universe, start channel (Art-Net/sACN offset within the first universe), colour order, pixel count, and the start (x0,y0) and end (x1,y1) of the line in canvas coordinates 0–1 with origin top-left. The canvas preview shows every line with the colours being sent right now (blue dot = pixel 1, pink = last). + add matrix builds a grid of rows for panels, with serpentine wiring if you ask. Press apply to master to save — the layout persists in master/config.local.json. Test patterns (white / R-G-B / chase) send regardless of the picture so you can check wiring and colour order.

    
Power — the bit that actually bites

    
    
      
  • WS2812 at full white draws ~60 mA/pixel: 150 px ≈ 9 A at 5 V. Budget 20 mA/px average with our brightness cap of 0.8 and dark-friendly scenes, but size the PSU for the peak.
    • 
      
  • Inject power every 3–5 m of 5 V strip (both ends of every 5 m reel); 12 V WS2815 tolerates 10 m. Voltage drop shows as the far end going orange — that's your cue.
    • 
      
  • Common ground between PSU, controller and strip; a 300–500 Ω resistor in the data line at the first pixel; keep the data lead short (< 1 m) or use a level shifter.
    • 
      
  • Fuse each PSU output. Strips on aluminium channel run cooler and last longer.
    •

Troubleshooting

    

      
Projectors table emptyRenderers can't see the master's multicast. Same subnet? IGMP snooping? journalctl -fu fractal-renderer should say "master acquired". Try --iface <pi-ip> on multi-NIC Pis.

      
"freewheel" in renderer logPackets stopped for >3 s. Master down, cable, or Wi-Fi drop. Picture keeps moving; it re-locks automatically.

      
Ableton Link shows no peersLink uses UDP multicast on 20808 — same switch, no client isolation, multicast allowed. Enable Link in Resolume's Tempo preferences. Both ends need to be on the same subnet.

      
LEDs stay darkSwitch on a test pattern first: if that works, it's the layout/source; if not, it's network or controller. WLED: DDP must be enabled under Sync; Art-Net: universe numbers start at 0 in WLED/Advatek but at 1 in some sACN gear. Check the strip's IP is reachable (self-test pings each).

      
Resolume ignores OSCPreferences → OSC → Input enabled, same port as here; Windows firewall must allow Resolume UDP in. Values are normalised 0–1 by design.

      
Pro DJ Link stays amberNo beat packets reaching the master: LINK cable, subnet (169.254 vs DHCP), or a deck that isn't playing. sudo tcpdump -ni eth0 udp port 50001 on the master shows them if they're there.

      
Low fps on a PiLower --scale (0.5 → 0.4) or iterations (150). Check vcgencmd get_throttled — 0x50000 means the PSU is weak.

      
Garbage / black on Pi 5 with KMSDRMUpdate: sudo apt full-upgrade (needs SDL ≥ 2.30). Or run under Pi OS Desktop without the KMSDRM line.

      
Audio never goes greenarecord -l must list the device; add the user to audio; master needs libportaudio2. Pick the device in the Sources panel.

      
MIDI never goes greenaconnect -l lists the controller? Set midi_port_contains in config if several ports exist.

      
Blank between tiles / seamsTiling assumes edge-to-edge, same-resolution projectors. Edge-blend feathering is on the roadmap.

      
projectM preset numbers don't match between PisPreset packs differ. Run install-projectm.sh (same flags) on every Pi and the master; the Renderers table flags any count mismatch.

      
Milkdrop slow on a PiHeavy presets are heavy everywhere. Lower --scale to 0.5, avoid Cream-of-the-Crop's shader-heavy ones, or keep auto-cycle on so a slow preset never lasts long.
